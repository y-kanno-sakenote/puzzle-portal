## FAIL詳細: 手番でない側の手が合法と判定される

`Kabusekko.isLegal` / `applyMove` は `move.player` を明示すると **`state.turn` と一致するかを確認していない**。

再現手順:
```js
const st = Kabusekko.initialState(); // turn: 'bottom'
Kabusekko.isLegal(st, {player:'top', from:'hand', size:3, to:0}); // → true（本来 false であるべき）
const ns = Kabusekko.applyMove(st, {player:'top', from:'hand', size:3, to:0});
// ns.board[0] = [{owner:'top', size:3}]  ns.turn = 'bottom'（top が指したのにbottomの番のまま）
```
画面側のドラッグ操作は `pointerdown` で `el.dataset.owner !== state.turn` を弾いており、かつ `onUp` で常に `move.player = state.turn` を渡すため、**現行UIからは実際には踏めない**（実機被害は無い想定）。ただし `window.Kabusekko` は「純粋ロジック」として外部公開されている（qa係の独立検証やAI対局のような将来の直接呼び出しを想定した設計）ため、契約としては壊れている。直った後の望ましい挙動: `move.player` が `state.turn` と異なる場合は常に `false`／`applyMove`は例外。

## [6] 合法手ゼロの局面について
数学的に閉じる: 「大(size3)」は互いに覆えないため一度盤に出たら常に見え続け、両者合わせて4個しか存在しない。ゆえに9マス中「上が大」のマスは常に4以下＝空きか大より小さい駒のマスが常に5以上残る。各自は大を必ず手駒か盤上（見えている状態）で持ち続けるので、大の一手（置くか動かす）が常に存在＝合法手ゼロは構造的に起こり得ない。
独立実装のみでの状態探索（40万局面、非終端34,771件、7.1秒）でも実測max_big_visible=4を確認し反例0件。40万局面は全数ではない（300万局面まで拡張しても未到達だったため打ち切り＝**未検証**は残るが、上記の構造証明で数学的には決着している）。
