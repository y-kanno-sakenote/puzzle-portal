# クエスト（仮称パズルレリック）仕様 v0.1

パズル箱のタイトル画面「クエスト」から入る。置き場所は `puzzle-portal/quest/`。

パズル箱のひとり用11本をステージにして、3ステージでスコアを掛け算で膨らませ、選んだ系統の並びでキャラが決まるスコアアタック。
**数値は全部叩き台**。自動プレイと実プレイで確かめてから確定する。

## 1. 流れ（1プレイ＝3ステージ）
1. 各ステージで、3系統から1本ずつ、計3本がランダムに出る
2. 1本を選んで解く。クリアするとそのステージの点（1〜1000）が決まる
3. 3ステージ解いたら、累計スコアとキャラが確定する

- 同じ系統を続けて選んでもよい。1プレイの中で同じゲームは二度出さない（各系統3本以上なので足りる。動かす系が4本になっても、同じ系統を選べる回数は1プレイ3回のまま変わらない）
- ギブアップしたら、そのプレイは**そこまでにクリアしたステージの累計**で終わり（キャラなし・2026-09-27改訂）。解いている途中のステージの持ち点は数えない（数えると、解くよりやめる方が得な場面が出る）。旧：スコア0で何も残らない

## 2. 系統（11本→3系統）
| 系統 | ゲーム |
|---|---|
| 🚗 動かす | 車をだせ！・箱入り娘・すべりロボ・にげこみ（2026-10-11追加） |
| 🧩 埋める | ナンプレ・星おき・ピクセル・はたたて（2026-10-14追加） |
| 🔗 つなぐ | みちつなぎ・くるくる・窓わけ |

## 3. 難易度（ステージが進むほど上げる）
- 1st＝易・2nd＝中・3rd＝難。ゲームごとの既存の指標（最短手数・盤サイズ・推論の強さ）で問題を機械的に3段に分ける
- 段の中からランダムに1問出す
- ゲームごとの分け方と問題数 → §7。**全ゲームに既存の難易度ラベル（tier）があり、問題の新規生成は不要**

## 4. スコア（掛け算インフレ）
- **桁の配分（案②・2026-09-25決定）**：ステージ点の上限は 1st＝100・2nd＝1,000・3rd＝10,000。難しいステージほど点が大きく動く
- 累計 = s1（〜100）→ s1×s2（〜100,000）→ s1×s2×s3（〜1,000,000,000）
- **桁ランク**：累計の桁数がそのままランク（天井は1st＝3桁・2nd＝6桁・3rd＝10桁）。桁が上がったら「↑」で示す
- 各ステージの上限は**天井**（保証ではない）。桁数がそのまま腕前になる（2026-09-25決定）
- **減点方式（2026-09-25決定・2026-09-27改訂）**：各ステージは持ち点＝上限から始まり、減っていく。0になったらアウト（ゲームオーバー）
  - **減るのは手数だけ。時間は採点にもアウトにも使わない（2026-09-27決定）**
  - 最短手数までは減らない。超えたら直線的に減り、**余分に打てる手数を使い切ると0＝アウト**
  - `持ち点 = round(上限 × max(0, 1 − (実手数−最短) ÷ max(最短×SLACK, FLOOR)))`、SLACK=2・FLOOR=10
  - 倍率だけだと最短の小さいゲームが厳しすぎる（すべりロボ入門は最短3手＝+6手でアウト、くるくる上級は最短142手＝+284手。**同じ「3倍」が47倍ちがう寛さになる**・2026-09-27 実測）。どのゲームでも最低10手は余分に打てるようにした。**SLACK と FLOOR は叩き台。実機プレイで詰める**
  - クリアした瞬間の持ち点がステージ点（最低1）。プレイ中は今の持ち点を表示し、最短を超えて減り始めたら赤くする
  - アウト時：そこまでの累計と桁数は見せる。キャラは3ステージ完走でのみ生まれる（アウトならなし）。「やめる」（ギブアップ）もアウトと同じ扱いで累計を見せる（§1）
  - **猶予時間Gと時間係数は廃止（2026-09-27）**。捨てた案：全ゲーム共通で易60秒・中120秒・難180秒、2Gでアウト。ナンプレや窓わけの上級は人間には180秒で解けず「解けたのに0点でアウト」が普通に起きるため。考える時間を罰さず、手を動かしすぎたときだけ落ちる形にした
  - 捨てた案：アウトを無くして点が減るだけにする（失敗する瞬間が無くなる）／お手つきN回でアウト（「明らかな間違い」をゲームごとに定義できない）
- **累計タイム**：3ステージのクリア時間の合計を参考として表示する（点には使わない・2026-09-25）
- 手数の数え方：
  - **手数の原則：答えに関わる状態が1マス変わるごとに1手**（2026-09-25・操作調査にもとづく）
    - ドラッグは「1回」ではなく「変わったマスの数」で数える。ドラッグの上手い下手で差が出ないようにするため
    - メモ・×印など、答えに関わらない印は数えない
    - 「もどす」自体は数えない（間違えた手はすでに数えられているので、帳消しにはならない）

    | ゲーム | 1手 | 最小手数 |
    |---|---|---|
    | 動かす系3本 | 駒を1回動かす（既存の手数カウント） | BFSの最短手数（`solve()`） |
    | にげこみ | 🏃が1歩動く（既存の手数カウント。捕まって「もどす」しても減らさない） | 問題データの `min`（BFSの最短） |
    | ナンプレ | 1マスの数字が変わる（置く・書き換え・消す） | 空きマスの数 |
    | 星おき | 1マスの★が付く・外れる（タップで×を経由しても★の出入りだけ数える） | ★の数 |
    | ピクセル | 1マスの塗りが付く・外れる | 塗るマスの数 |
    | はたたて | 安全マスを開けるタップ1回（0の連鎖でまとめて開いても1手。🚩は数えない。🕳️に落ちたタップも1手で、「もどす」しても減らさない） | 問題データの `min`（3BV＝閉じた0のつながりの数＋どの連鎖でも開かない数字マスの数。生成器で計算） |
    | みちつなぎ | 道が1マス伸びる（逆になぞって消すのは数えない。消えた所を引き直せば数える） | 全マス数 − ペアの数 |
    | くるくる | 1回タップ（90°回転） | 各マスを正解の向きにする最少回転の和（直線は180°、十字は回転で見た目が変わらない点を考慮） |
    | 窓わけ | 1マスの所属する部屋が変わる。「できた」で不正解も1手 | 全マス数 − 部屋の数（初期状態が1マス1部屋であることを2026-09-27にコードで確認済み） |

## 5. キャラ（27体・仮）
- 3ステージで選んだ系統の並び（3×3×3＝27）がキャラになる
- 仮の名前の付け方：**1st＝種族・2nd＝気質・3rd＝称号**の組み合わせで自動的に決める

| | 🚗 動かす | 🧩 埋める | 🔗 つなぐ |
|---|---|---|---|
| 1st 種族 | 歯車族 | 石板族 | 糸族 |
| 2nd 気質 | せっかちな | 几帳面な | 人懐っこい |
| 3rd 称号 | 走り屋 | 職人 | 案内人 |

例：🚗🧩🔗＝「几帳面な歯車族の案内人」。名前と絵は後で差し替える

## 6. レア（隠し要素）
次のどちらかを満たすと、そのキャラが **✨レア版** になる。
- **キリ番**：累計スコアの数字の並び
  - **掛け算で作れる数からしか選べない**。9桁のぞろ目・123,456,789 などは、1000を超える素数を含むので作れない（機械で全数確認済み）
  - 候補：下3桁が777、777,777、77,777,777、123,456、1,234,567
  - 1版目（パズルだけ）：満点の 1,000,000,000 は1通りしかない＝最上位の隠し
  - 2版目（早撃ち・ボス込み）：10億は223通りで作れるようになり隠しではなくなる。最上位の隠しは満点の 40,000,000,000（全部最小手数＋早撃ち2勝＋ボス最大）に移る（2026-09-25 機械で確認）
- **パズルごとの条件**：3ステージのうちどこかで達成すればよい
  - **クエスト対応の全ゲーム共通：最小手数ぴったりでクリア**（2026-09-25決定）

## 8. 組み込み方
**共通の障害**：9本とも、外から問題を指定する口（URL引数）がなく、クリアを外に知らせる仕組みもない。保存キーも各ゲーム固有なので、そのまま iframe で遊ばせると本家パズル箱の進み具合が書き換わってしまう。

- **案A（推奨）**：各ゲームに「レリックモード」を足す（1本あたり20行程度）
  - `?relic=<問題番号>` で開くと、その問題だけを表示する
  - 問題一覧・前後移動を隠し、進み具合を保存しない
  - クリアしたら親に `postMessage({solved, moves, ms})` を送る
  - 本家の遊び方は一切変わらない。GitHub Pages では `y-kanno-sakenote.github.io` の下が同じオリジンなので、別リポジトリからでも呼べる
- 案B：ロジックをこのアプリにコピーする。パズル箱には触らないが、9本分のUIが二重になり、直すたびにズレる
- 2026-09-25：パズル箱の中に `quest/` を置き、入口をタイトル画面（パズル／クエスト）にすると決定。組み込みは案A（各ゲームにクエスト用モード）で進める

## 9. 2版目：幕間の早撃ちとボス（2026-09-25決定・1版目では作らない）
1版目の3ステージで「手数の採点が面白いか」を確かめてから足す。

| 順番 | 中身 | 強さの調整（叩き台） | ごほうび |
|---|---|---|---|
| 1st | パズル（易） | | |
| 幕間1 | はやつかみ早撃ち | コンピュータが2.0秒で取る（当初1.2秒は実機で勝てず 2026-10-01 変更） | 勝てば累計×2 |
| 2nd | パズル（中） | | |
| 幕間2 | はやつかみ早撃ち | コンピュータが1.5秒で取る（当初0.8秒） | 勝てば累計×2 |
| 3rd | パズル（難） | | |
| ボス | かぶせっこ（ボスが先手） | 読みの深さを1手ごとに1・2・2・3から選ぶ | 勝てば×2〜×10（少ない手数で勝つほど高く、最大×10） |

- 早撃ち：札1枚の一発勝負。先に正しい品を引き寄せたら勝ち。お手つき（違う品）は負け。負けても累計は減らない
- ボス：負けても累計はそのまま（上積みを狙う挑戦）
- 桁の天井：パズル3本＋早撃ち＝最大40億（10桁）。**11桁はボスを倒した人だけ**（最大400億）
- 本家のはやつかみ（向かい合い専用）・かぶせっこ（コンピュータの相手は足さない）には手を入れない。クエストの中に1人用を別に作る
- **組み込み（2026-10-01・実験ブランチ exp/quest-boss）**
  - 各ステージの結果画面で「つぎへ」を押すと、幕間（`hayauchi.html?cpu=2000`／`?cpu=1500`）・ボス（`boss.html`）を同じ iframe に開く。決着は1回だけ `{type:'quest-duel', win}`／`{type:'quest-boss', win, moves}` で受け、その段階にいるときだけ・1回だけ数える
  - 結果（勝ち ×N／負け・累計・桁）はステージの結果画面を使い回して見せる。最後の画面にボスの結果を1行
  - 幕間・ボスの間は持ち点の帯と「やめる」を出さない（早撃ちは一瞬・ボスには降参がある）。持ち点の減点も無い
  - **ボスが先手**（2026-10-01）。遊び手が先手だと、深さ2のボスには「ボスがどう応じても5手で必ず勝てる筋」があった（かぶせっこは先手必勝）。ボスの初手も同じ評価の手から無作為
  - **読みの深さは1手ごとに 1・2・2・3 から選ぶ**（`DEPTHS`・叩き台）。深さを1つに決めると、ボス先手でも必ず勝てる筋が残る（深さ1と3は5手・2は6手）。混ぜると8手以内に無い（ボスの選び方しだいなら最短3手）
  - 実測（2026-10-01・ボス先手・各2000局）：でたらめに指す人 0.1%／初心者役（1手先の勝ちを取り・塞ぐだけ）19.6%・手数の中央6／3手読み 66.7%・中央5。打ち切りはほぼ0
  - **ボスの倍率 = min(10, max(2, 13 − 遊び手の手数))**：3手で勝てば×10、11手以上は×2。負け・降参・打ち切りは×1。3手読みの勝ちの7%が3手（×10）で、×2〜×10はどれも実際に出る。**13・10・2 は叩き台**（`BOSS_TOP`・`BOSS_MAX`・`BOSS_MIN`）
  - キャラは3ステージ完走で生まれる（ボスの勝ち負けに関係ない）。ボスで負けても最後の画面へ進む。記録（§11）はボスの後の累計で残し、上限は400億
  - レアの条件（最短ぴったり・キリ番）は変えない。キリ番は最後の累計で見る

## 11. 自分の記録（2026-09-30）
- 1プレイが終わるたび（完走・アウト・ギブアップ）、**この端末の中だけ**に記録を残す（localStorage `quest-records`）。どこにも送らない。他の人とは比べない
- 満点（1版目＝10億、2版目＝400億）を超える記録は書き換えられたデータとして読まない
- 1つもクリアしていないプレイは残さない。点の高い順に上位10件、同点はタイムの速い方が上
- 1件に持つもの：点・クリアしたステージ数・終わり方・タイム・日時・選んだ系統の絵文字・キャラ名（完走のみ）・✨レア
- 見せ方：タイトルの「きろく」から別画面。1件1行で「系統の絵文字＋✨｜点」だけ（順位・桁・キャラ名・終わり方・タイム・日付は出さない）。「きろく」は記録0件でも出す（下に §12 の「みんな」があるため・2026-10-15）
- **遊んだ人の名前（2026-10-15 オーナー要望）**：終わりの画面の名前の欄（前回の名前入り・`quest-board-name` を §12 と共用）に打った名前を、その回の記録に `player` として残す（打ち直せば書き換わる・決まりは §12 の名前と同じ・不正や空なら名前なし）。名前のある記録は「みんな」と同じ「名前＋小さな絵文字｜点」、昔の記録は今まで通り
- 終わりの画面では、1位に入ったときだけ「自己ベスト」（初めてのプレイは除く）
- 消すボタンは付けない（10件で下位は押し出される・誤タップで戻せない）
- 捨てた案（2026-10-14 に §12 のボードとして作り直した・2026-10-15 から誰でも載せられる）：みんなで共有する掲示板（GitHub Pages に保存先が無く外部が要る・点はブラウザで計算しているので誰でも好きな点を書き込める・憲法の改定が要る）／結果をURL・画像で共有

## 12. みんなの記録（2026-10-14 オーナー決定・2026-10-15 合言葉を外す）
クエストの点を1つのボードに載せて見比べる。**誰でも見られて、誰でも載せられる**（ログイン・合言葉なし）。§11（自分の記録）はそのまま残す。
- **公開範囲**：誰でも。合言葉のころの `#board=<合言葉>` 付きの URL は無害に無視し、アドレス欄から消すだけ。localStorage に残った `quest-board-key` は読まない
- **対象**：クエストの点だけ（各パズルの問題ごとのランキングは作らない）
- **載せ方**：終わりの画面（完走・アウト・ギブアップで1ステージ以上クリアしたもの）に名前の欄と「みんなに載せる」（「もう一度」の下に控えめに置く）。名前（1〜12文字）を入れて送る。名前はその端末に覚える（`quest-board-name`）。載ったら順位を「みんなで3位」のように1行で出す（100位の外なら「届きませんでした」）。失敗は「つながりませんでした」「載せられませんでした：理由」。つながらなくても他は今まで通り動く
- **見せ方**：タイトルの「きろく」（自分の記録が0件でも出す）で、自分の記録（じぶん）の下に「みんな」。自分の記録と同じ1件1行（系統の絵文字＋✨｜点）に名前を足す。順位の数字は出さない。上位100件（点の高い順・同点はタイムの速い順）
- **通信**：置き場所へは「きろく」を開いたとき（読む）と「みんなに載せる」を押したとき（送る）だけ。タイトル画面を開いただけでは通信しない
- **送るもの**：名前・終わり方（clear/out/giveup）・各ステージ（game・level・moves・min）・早撃ちの勝ち負け（クリアしたステージの数だけ、最大2つ）・ボス（完走のみ：勝ち負け・手数）・累計・タイム・キャラ名・レア
- **置き場所**：Cloudflare Worker `puzzle-quest-board`（`worker/`）＋ Durable Object 1個に上位100件。見る・載せるに鍵は要らない（呼べるページは `ALLOWED_ORIGINS` で絞る）
- **ずる対策（軽い・置き場所の側で）**
  - game がどれかの系統にあり、level がそのステージの段（`QUEST`）の範囲にある。1プレイで同じゲームが二度出ていない
  - min が**その問題の本当の最小手数**と一致し、moves ≥ min（最短より少ない手数を弾く）。持ち点が尽きる手数も弾く
  - 本当の最小手数の表は `worker/tools/build_mins.mjs` が各ゲームの問題データから機械で作る（11本・470問。各ゲームのクエスト用モードが送る min と同じ数え方で、その数え方の行がゲーム側に残っているかも確かめる）。2026-10-14 に全470問がゲームの送る min と一致することをブラウザで確認
  - 手数・最短・早撃ち・ボスから累計を §4・§9 と同じ式で計算し直し、送られた累計と一致すること（上限400億）。キャラ名・レアも計算し直して照らす
  - 名前は前後の空白を削り、制御文字・改行・ゼロ幅などを弾く。見える文字が1つも無い名前（ハングルのフィラー U+3164・点字の空白 U+2800・各種の空白類・ゼロ幅だけ）も弾く。**ZWJ でつないだ絵文字（👨‍👩‍👧 など）は使えない**（つなぎの文字で弾かれる・2026-10-14 そのままと判断）
  - 連投は1つの IP から1分に3件まで（`RATE_PER_MIN`・叩き台）
  - 管理鍵の総当たり止め：削除の鍵違いの 403 を IP ごとに数え、1分に10回を超えたら、その IP は1分間、**正しい管理鍵も含めて**削除の要求を 429 にする（`BAD_KEY_PER_MIN`・叩き台）。制限中は鍵を見ずに同じ応答を返す＝当たり外れが見分けられない。見る・載せるは数えず、止めもしない
  - タイムは7日まで受ける（タブを開いたまま放置しても弾かない。タイムは表示だけで点に使わない）
  - 手順そのもの（盤の動き）は確かめない＝手数を偽ることはできる。遊びのボードなので割り切る（荒れたらオーナーが消す）
- **削除**：オーナーが1件ずつ消せる（別の secret `ADMIN_KEY`・`DELETE /entries/:id`。手順は `worker/README.md`）。遊ぶ人の画面に消すボタンは付けない
- **ゲームの問題を足し替えたら**：`cd worker && npm run mins` で表を作り直し、`npm test` を通してから Worker をデプロイし直す（作り直さないと新しい問題の記録が弾かれる）。採点の式・段の範囲を変えたら `worker/src/rules.js` も直す（テストが quest/index.html と突き合わせる）
