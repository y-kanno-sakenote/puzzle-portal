# はたたて 仕様 v0.1（2026-10-13・叩き台）

運の要素が無い、数字から穴の位置を推理して開けていく型。名前は仮称。

## 完成条件（観測可能）
初見の人が (1) 開いてすぐ盤が見え（一部のマスは最初から開いている） (2) マスを押して開け、切り替えで🚩を立てられ
(3) 当てずっぽう無しに🕳️以外を全部開けてクリアし (4) 🕳️を開けても「もどす」で続けられ (5) 次の問へ進め
(6) 閉じて開き直しても進み具合が残っている。スマホの縦画面（幅360px）で片手で遊べる。

## 規則
- 長方形の盤に🕳️（落とし穴＝地雷）が隠れている。開いたマスには周り8マスの🕳️の数が出る（0は空白）
- 🕳️以外を全部開ければクリア。**🚩は答えに関わらない**（クリア判定は「安全マスを全部開けた」だけ）
- 0のマスを開けると、周りを自動で開ける（連鎖）
- **始まりの状態で一部のマスが開いている**：0のマス1つと、そこから連鎖で開く範囲。最初の一手の運を無くす
- **推理だけで最後まで開けられる盤面だけを採る**（下の段階ソルバーで全安全マスが開けるもの）
- 🕳️を開けたら「おちた！」。そのマスを赤く出し、盤は止まる。**「もどす」で1手前に戻って続けられる**（にげこみの「つかまった」と同じ流儀。最初からにしない）
- 画面右上に「のこり」＝🕳️の数 − 立てた🚩の数（負にもなる）。盤全体の残り地雷数は推理に要る情報なので出す

## 操作
- 「ひらく／🚩 はた」の切り替えボタン（既定は ひらく）。スマホの長押しは誤爆しやすいので使わない
  - ひらく：閉じたマスを開ける。🚩のマス・開いたマスは何も起きない
  - はた：閉じたマスの🚩を立てる／外す
- 「もどす」（1操作戻る。旗も1操作）／「はじめから」（始まりの状態へ）
- クリアで「クリア！」→「つぎへ」。レベル一覧（段ごと・クリア済みに✓）
- 足さないもの：開いた数字を押して周りを一気に開ける操作（いわゆるコード）、自動で🚩を立てる、タイマー、ヒント、自動解答、音、日本酒テーマ、クエスト（`?quest=`）

## 推論の段（段階ソルバー。`tools/gen_levels.py` と `window.Hatatate.solve` は同じ定義）
局面＝開いたマス・確定した🕳️・閉じたマス。各回、弱い段から試し、何か決まった段の発見を**全部まとめて**適用して段1に戻る（適用順に依存しないので Python と JS で必ず同じ結果）。安全と決まったマスは開ける（0なら連鎖）。

| 段 | 中身 |
|---|---|
| 段1 | 1つの数字だけで決まる（残りの🕳️＝閉じた隣の数なら全部🕳️、残り0なら全部安全）。**盤全体の「のこり」だけで決まる場合**（のこり0なら閉じたマスは全部安全／のこり＝閉じたマスの数なら全部🕳️）も段1に含める |
| 段2 | 重なる2つの数字の比べ合い（2つを連立し、共通部分・片方だけの部分の🕳️の数がどの場合も 0 か満杯なら確定。部分集合・1-2の形を含む） |
| 段3 | 3つ以上の数字の連立（数字でつながったひとかたまりの全解を列挙し、どの解でも同じになるマスを確定） |
| 段4 | 「のこり」を数字と組み合わせて使う（かたまりどうし＋数字に接しないマスを、盤全体の残りの🕳️の数で連立） |
- 全解の列挙は 200,000 節点で打ち切り（超えたら重すぎとして生成で捨てる。採用40問では一度も超えない）
- 「最も強い段」＝使った段の最大

## 段（各10問・計40問）
| 段 | 盤（列×行） | 🕳️ | 密度 | 採用条件 | 採用40問の実測（開始時に開いている割合／段1〜4を使った回数） |
|---|---|---|---|---|---|
| 入門 | 6×8 | 8 | 17% | 段1だけで解ける | 10〜15%（平均14%）／段1 5〜15 |
| 初級 | 8×10 | 14 | 18% | 最も強いのが段2・段2を2回以上 | 9〜23%（15%）／段2 5〜9 |
| 中級 | 8×12 | 19 | 20% | 最も強いのが段3 | 10〜23%（14%）／段2 1〜6・段3 2〜3 |
| 上級 | 9×14 | 26 | 21% | 最も強いのが段4・**段3も1回以上** | 8〜21%（13%）／段2 3〜9・段3 2〜5・段4 1 |
- 叩き台は 初級8×10・中級9×12・上級10×14 だった。押しやすさの最低ラインを**幅360pxでマス36px以上**（約9.5mm）と決め、列を9以下にした（中級8列＝42px、上級9列＝37.7px。入門・初級は48px上限）
- 段4は候補のほぼ全部で「終盤の1回」だけ。段4だけで上級にすると段3を一度も使わない盤が多いので、上級は段3も要る盤に絞った（「段4が要る（または段3を多用）」の両方を満たす形）
- **開始時に開いている割合の目安：安全マスの 8〜30%**。0のマスの連鎖のうち、この範囲で**小さい入口から**試して、段の条件を満たす最初のものを採る（入口は最小限）
- **始まりに見える盤が同じ問題は採らない**（2026-10-13 qa）：開始時に開いているマスの位置と数字を、左右・上下反転・180度で同一視して比べ、同じ段の既採用と同じなら捨てる（🕳️の配置が違っても遊び手には同じ問題に見えるため）
- 10問の選び方（`select_key`）：入門＝開始時に開いているマス数の少ない順（入口は最小限）／初級＝段2の回数の多い順／中級＝段3の回数→段2の回数の多い順／上級＝段3＋段4の回数→段2の回数の多い順。ただし**始まりのマス（start）が盤を3×3に分けた同じ区画にあるのは2問まで**（足りなければ3問まで緩める）。採用40問は各段6〜7区画に散った
- 段の中の並び（`order_key`・やさしい順）：次の鍵の小さい順に並べる
  - 入門：段1の回数 → 開始時に開いているマス数の多い順 → start の番号
  - 初級：段2の回数 → 開始時に開いているマス数の多い順 → start の番号
  - 中級：段3の回数 → 段2の回数 → 開始時に開いているマス数の多い順 → start の番号
  - 上級：段3＋段4の回数 → 段2の回数 → 開始時に開いているマス数の多い順 → start の番号
- 似すぎの判定：同じ段の候補どうしで、🕳️の配置の Jaccard 係数（恒等・左右反転・上下反転・180度回転の4通りの最大）が 0.5 以上なら後のものを捨てる

## 生成（`tools/gen_levels.py`・標準ライブラリのみ）
- 段ごとに：ランダムに🕳️を置く → 0の連鎖の範囲を小さい順に → 段階ソルバー → 条件を満たせば候補（似すぎ・始まりに見える盤が同じものは捨てる）。候補200で止め、上の基準で10問選ぶ
- 出力 `tools/levels.json`：`{"tier","w","h","mines":"0/1の文字列（行優先）","start":最初に開ける0のマス,"hardest","uses":[段1..4の回数],"open":開始時に開いているマス数}`
- `index.html` の `/* LEVELS-BEGIN */`〜`/* LEVELS-END */` に埋め込む（`--keep tools/levels.json --embed index.html`）。`--check tools/levels.json` で解き直して確かめる
- 実測（seed 20261013・見える盤の重複除外を入れた版）：採用率（盤→候補200）入門 2.7%（7,424枚）・初級 24%（850枚）・中級 2.4%（8,431枚）・上級 1.0%（20,035枚）。全体で約46秒

## 純粋ロジック `window.Hatatate`（DOM 非依存）
`LEVELS`・`load(level)`（盤：w,h,N,mines,nums,nb,total,start）・`startState(board)`・`open(board,state,i)`（{result:'boom'|'open'|'none', state, opened}。元の state は変えない）・`toggleFlag`・`isClear`・`minesLeft`・`solve(level)`（{solved,hardest,uses,opened0}）

## 保存
- localStorage キー `hatatate`：`{cleared:{idx:1}, last:idx}`。try/catch、`last` は `Number.isInteger` と範囲で確かめる。入口 `../index.html` の進み具合（`data-key="hatatate" data-n="40"`）が読む
- 遊んでいる途中の盤は保存しない（開き直すと始まりの状態から）

## 画面（最小限。文言・形・色・絵柄は ui係が見直す）
- 数字の色：1＝青・2＝墨・3以上＝赤（`:root` の既存の変数 `--blue`・`--ink`・`--red`。新しい色は足していない）。閉じたマスは `--frame`
- 🕳️＝落とし穴（地雷。💣は避けた・🕳️は「集めるもの」に見えるので不採用）、🚩＝旗
