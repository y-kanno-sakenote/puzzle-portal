# index=35 独立検証（2026-09-14）

## 経緯
通し検証（`qa_check.py`、マス単位の領域成長・フロンティア方式）は index=35 を
node_budget=60,000,000・300秒でも打ち切りのまま収束しなかった（2026-09-13）。
実装側（`window.MadoWake.countSolutions`／生成器）は同じ盤を2秒未満で一意解と判定するが、
探索の考え方を共有している疑いがあり、これでは独立確認にならない。

## 盤とルール
- n=8（8×8）、rules=`size + color + rect`、tier=上級
- cells: `4.4....4............4.3.254..BR.....R..3..2.4Y.B4..6.4B..4......`
- solution: `aabbbbccaadeffccghdeffijghdeklijmhdeklijmhnekoopmhnekqqpmrrrrqqp`

## 新しい探索方針（`tools/qa_indep35.py`）
`rect` ルールがある＝すべての領域が長方形になることに着目し、既存の
「マスをフロンティアから1つずつ足す領域成長」とは別パラダイムの
**長方形タイル敷き詰め問題（exact cover）**として解いた。

- 盤に置きうる全長方形をあらかじめ列挙し、size/color 制約で静的にふるいにかける
  （成長法のような逐次判定ではなく事前フィルタ）
- 探索は Algorithm X 流に「未確定マスのうち候補数が最も少ないマス」を毎回選んで分岐（MRV）
  （`qa_check.py` はマス番号昇順に固定して試すだけ）
- 状態は64bitビットマスク1個で管理し、到達済みで失敗した被覆状態をメモ化して再訪を防ぐ

## 結果
- 経過時間 = 0.0秒、ノード数 = 24、timeout=False
- 解の数（上限2で打ち切り） = **1**
- `puzzles.json` の `solution` と一致: **True**

## 判定
PASS。rect制約により長方形タイリングとして解くと探索空間が劇的に縮小し（24ノード）、
瞬時に一意解が確定した。マス単位の成長法が同じ問題で6000万ノード超も収束しなかったのは
パズルの欠陥ではなく、そのアルゴリズムと本個体の相性が特に悪かったため（探索順序依存の
性能限界）と判断できる。

## 提案
このまま出す（index=35 の一意性は別パラダイムの独立ソルバーで確定した。作り直し不要）。
