# おしだし 仕様 v0.1（2026-10-14・叩き台）

## 完成条件（観測可能）
初見の人が (1) 開いてすぐ盤と5行のルール（あそびかた）が見え (2) 矢印をタップして手持ちを押し込み（初級以上は手持ちをタップで回し）
(3) 駒から ◎ まで通路がつながった瞬間にクリアと分かり (4) 次へ進め (5) 閉じて開き直しても進み具合が残っている。
スマホ縦・片手。幅360pxで横スクロールしない。

## 盤
- n×n の正方形（5×5 か 7×7）。各マスに通路タイルが1枚。座標は左上 (0,0)、マス番号 i = r*n + c
- タイルは3種: **直線**（向かい合う2本）・**かど**（直角の2本）・**三叉**（3本）。十字・行き止まりは使わない
- **押せる列は1つおき**: 0始まりで奇数番目の行・列（5×5 は 1,3／7×7 は 1,3,5）。押せる列の両端に押し込み口（矢印）
- **偶数行かつ偶数列のマスは動かない**（盤上で少し濃く塗る）。それ以外のマスは、通る押せる列が押されると動く

## 1手（押し込み）
- 手持ちのタイルが1枚。押し込み口を押すと、手持ちがその端のマスに入り、列が1マスずれ、
  **反対側の端から押し出された1枚が次の手持ち**になる。**1手＝押し込み1回**
- **打ち消しの禁止**: 直前に押し込んだ口の**反対側の口**（＝いま押し出された1枚が出た口）は、次の1手では使えない。
  画面ではその矢印を薄くして押せなくする。回せる段で向きを変えても同じく禁止（元のゲームと同じ規則・手数の意味を保つため）。
  1手あけた後なら使ってよい
- **回転**: 入門は手持ちを回せない（押し出されたままの向きで入る）。初級以上は押し込む前に手持ちをタップで時計回り90°ずつ回せる。
  **回すのは手数に数えない**

## 駒とゴール
- **駒（赤い●）**: タイルの上に乗っていて、列がずれると一緒に動く。押し出されたら、反対側の端（入ってきた手持ちのタイルの上）に回り込む。駒は自分では歩かない
- **ゴール（◎）**: 動かないマスに置く（動くと見失うので）
- **クリア**: 駒のマスからゴールのマスまで、通路が一続きにつながった瞬間（隣り合う2マスは、両方の腕が向かい合っているときだけつながる）
- 駒から届くマスは濃い青、届かないマスは薄い色で描く（くるくると同じ「状態の描画」で、答えではない）。クリアの瞬間、駒からゴールまでの通り道を橙で光らせる

## 手数・操作
- 画面に「手数 ／ 最短」。最短以内でクリアしたときだけ ★
- もどす（1手戻す。手持ちの向きも押す前に戻る）・はじめから・レベル一覧（段ごと）・クリアで「つぎへ」
- 押し込むと列が約0.17秒で1マス滑る。押し出された1枚は盤の外へ滑って消え、手持ちの枠に現れる

## 記法（`tools/levels.json` と `index.html` の LEVELS）
`{"firsts":f,"n":5,"cells":"25文字","hand":"1文字","piece":i,"goal":i,"rot":0|1,"min":k,"sol":[[op,向き],...],"tier":"入門"}`
- `cells`・`hand`: 各タイルの腕を N=1 E=2 S=4 W=8 の和の16進1桁（くるくると同じ）。時計回り90°は1ビット左巡回
- `piece`・`goal`: マス番号
- 押し込み口の番号 `op`: 押せる行ごとに [左から, 右から]、続いて押せる列ごとに [上から, 下から]
  - 5×5: 0=行1左 1=行1右 2=行3左 3=行3右 4=列1上 5=列1下 6=列3上 7=列3下
  - 7×7: 0〜5=行1・3・5の左右、6〜11=列1・3・5の上下
- `sol`: 生成器が見つけた最短手順の1例（押し込み口と、押し込んだときの手持ちの向き）。qa の突き合わせ用
- `firsts`: 最短手数の解につながる初手（押し込み口×向き）の数。少ないほど考えどころが狭い
- `nsol`: 最短手数の解（押し込み口と向きの列）の数。途中でつながる列は数えない（qa の全数列挙と同じ数え方）
- `needrot`: 回さないと最短手数で解けない盤なら1（回せない規則で解くと最短より長い、または解けない）。入門は常に0

## 生成（`tools/gen_levels.py`）
- ランダムな盤（直線:かど:三叉 = 3:4:3）・ゴールは動かないマス・駒は動くマスでゴールからマンハッタン距離 n//2+1 以上
- 局面（盤の全タイル・手持ち・駒・次に使えない口）で幅優先探索し、つながるまでの最短手数を出す。
  回せる段は「向きを決めて押す」を1手として展開し、直線の180°のように同じ形になる向きは同一視（局面の手持ちは形だけで持つ）
- 盤は腕ごとの4枚のビット盤で持ち、押し込みはシフトとマスク、つながりはビットの塗り広げで判定する
- **良い問題の条件**
  - 最初からつながっていない／最短手数が段の帯（入門3〜4・初級3〜5・中級3・上級4）に入る／探索の深さの上限（入門4・初級5・中級3・上級4）以内で解ける
  - **素直な手では届かない**: 次のどれかで最短手数以内に届く盤は捨てる
    - (a) 駒の乗っている列だけを押す（駒を動かすだけで済む）
    - (b) **どの時点でも、ゴールに一番近づく手（駒から届く範囲とゴールのマンハッタン距離が一番小さくなる手・同点は全部）を選び続ける**。
      局面ごと（親ごと）に一番の手を選び、その全分岐を打ち切りなしで調べる（同じ局面はまとめる。30万局面を超えたら素直とみなして捨てる）。
      あわせて「その手番の全局面の中で一番の手だけを残す」読み方（400局面まで）でも届かないことを確かめる
  - **段の中で飛び抜けて易しくない**: 最短につながる初手（`firsts`）が5以下。最短の解の数（`nsol`）が、その段で採った10本の中央値の5倍以下
  - **回さないと解けない**（初級・中級・上級）: 回せない規則で解くと最短手数で届かない（`needrot`=1）。7×7 でも作れたので緩めていない
  - **似すぎた問題を避ける**: 同じ大きさの既採用盤と、同じ位置に同じタイルがある割合が 0.5 を超えたら捨てる
- 条件を満たした盤を（初級・中級は30本、上級は20本）集め、最短手数の大きい順、同じなら `firsts` の少ない順に10本を採る。
  `nsol` が中央値の5倍を超える盤があれば外して採り直す。段の中は易しい順（最短手数の昇順、同じなら `firsts`・`nsol` の多い順）に並べる
- 結果を `tools/levels.json` に書き、`index.html` の `LEVELS-BEGIN`〜`LEVELS-END` に埋め込む。seed 20261014
