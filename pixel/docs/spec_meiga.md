# ピクセル「名画」段階 仕様 v0.1（2026-09-09・叩き台）

著作権の切れた名画（浮世絵）をドット絵のロジックにし、**解き切ると元絵がカラーで出る**。
ドット絵は人（AI）が元絵を見て主役を起こしたもの。**機械の二値化は使わない**（写真モードで失敗が確定している）。

## なぜ
ロジック単体は報酬が「小さい絵1枚」で薄い。元絵という報酬を外から持ってくれば、ドット絵は低情報量のまま保てて、
「解く楽しさ」と「見る楽しさ」が競合しない。写真モードで詰まった構造をここで回避する。

## 素材の条件（守れないものは採らない）
- パブリックドメインであることが**提供機関のデータで明示**されているもののみ（例: Art Institute of Chicago の `is_public_domain: true`）
- 取得元・作者・原題・年代・所蔵・ライセンス・取得日を `docs/artworks.json` に台帳として残す。台帳にない画像は使わない
- 画像は幅600px前後のJPEGにしてリポジトリに置く（`art/` 配下、1枚150KB以下）
- 画面に必ず「作者・原題・年代・所蔵」を出す。ライセンス表記も添える
- 取得は `tools/fetch_art.py`（AIC API。`AIC-User-Agent` ヘッダが要る）。台帳と画像を同時に更新する

## 問題の作り方
1. 元絵を見て、**主役を1つ選ぶ**（波・富士・傘・雁・猫・とっくりなど）
2. **25×25** のドット絵に起こす（2026-09-09 変更。15×15・20×20 では元絵の特徴を捨てざるを得なかった）。既存の絵の基準を守る＝輪郭の内側に白い抜きを1〜3か所、ベタ塗り禁止、塗り率35〜55%
3. 一意解、かつ仮定なし（行・列の伝播のみ）で解けることを機械で確認。満たさなければ1〜2マス直す
4. 難度は既存の指標Dで測る。段階内は昇順

## 問題記法（既存に足す）
既存の問題に任意の項目 `art` を足す。無ければ従来どおり。
`"art": {"id":"aic-4371","file":"art/aic-4371.jpg","title":"東海道五十三次之内 浜松","artist":"歌川広重","date":"c. 1837/42","holder":"シカゴ美術館","license":"Public Domain (CC0)","source":"https://www.artic.edu/artworks/4371"}`

## 完成画面
- いつもの「完成」に続けて、**元絵をカラーで大きく出す**。その下に1行で「歌川広重 東海道五十三次之内 浜松 c.1837/42 シカゴ美術館 Public Domain」
- 画像は完成するまで読み込まない（先に見えたら台無し。`loading="lazy"` ではなく完成時に `src` を入れる）
- 「つぎへ」はいつもどおり

## v0.1 の範囲
- 名画10問（すべて25×25）。段階名は「名画」。実測 D=422〜954（2026-09-09 描き直し後。正は docs/spec.md の表）
- 主役は浮世絵から。酒器・酒宴の絵が採れれば1〜2問入れる

## 足さないもの
- 元絵の機械二値化／元絵のスライドショー／解説文の長文／外部APIへの実行時アクセス（画像はリポジトリに置く）
