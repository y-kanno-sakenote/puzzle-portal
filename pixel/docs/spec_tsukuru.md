# ピクセル 作成モード 仕様 v0.1（2026-09-14・叩き台）

自分で絵を描いてお絵描きロジックの問題を作り、URLで人に渡す。独立ページ `tsukuru.html`。
**既存60問の `index.html` には手を入れない**（検証済みの本体を壊さないため。入口のリンク1本だけ足す）。

## なぜピクセルだけか
箱の11本すべてに検証器が入っているが、**作ったものが人に見せられる成果物になるのはピクセルだけ**。
他のゲームで盤を作っても「問題を作った」で終わるが、ピクセルは「絵を描いた」になる。
写真モードが失敗したのは写真の情報量が多すぎたからで、**人が手で描いた小さい絵は成立する**（既存60問がその証拠）。作成モードは写真モードの正しい姿でもある。

## 画面と流れ
1. **大きさを選ぶ**: 10×10／15×15／20×20／25×25（既定 15×15）
2. **描く**: マスをタップで塗る／消す。指でなぞって連続で塗れる。「ぜんぶ消す」だけ置く
3. **たしかめる**: 押すと機械が判定し、次のどれかを返す
   - **これで作れます**（解が一つ、仮定なしで解ける）＋ 難度の目安（既存の指標Dで 入門／初級／中級／上級／特級／達人）
   - **答えが2通り以上あります**（一意でない）
   - **勘に頼らないと解けません**（行と列の伝播だけでは解けない）
   - **なにも塗られていません**
4. **名前をつける**（任意・既定「むだい」）
5. **わたす**: URLをコピーするか共有する。開いた人は解く画面へ

## 直さない（重要）
写真モードのような**自動の修復（マスを勝手に反転させる）は入れない**。描いた人の意図した絵を機械が書き換えるのは筋が悪い。
作れないと言われたら、描いた人が自分で1〜2マス直す。何が問題かだけ伝える。

## 共有のかたち
- `#p1.<w>.<h>.<base64url のビット列>.<名前を encodeURIComponent>`
- 開いた側は復元し、**その場でもう一度検証してから**遊ばせる（通らなければ「この問題は開けません」）
- 写真は関係しない。ビットだけ。25×25 で 105文字程度

## 解く画面
- `index.html` と同じ作法（行と列の数字・タップで塗る・×メモ・途中で正誤を言わない・全部塗れたら完成）
- 完成したら名前を出す。「じぶんも作る」で作成画面へ

## 保存
- localStorage キー `pixel-tsukuru`: `{made:[{bits,w,h,title,date}]（最大20件）}`。作ったものの一覧から作り直せる
- 既存の `pixel-v2`（60問の進み具合）には触らない

## 足さないもの（v0.1）
- 自動修復／ヒント／自動解答／タイマー／ライフ／サーバー・投稿一覧・ランキング／写真の取り込み／色
