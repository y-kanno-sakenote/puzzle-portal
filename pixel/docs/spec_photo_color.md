# ピクセル 写真モード・4色版 仕様（2026-09-08）

線画（XDoG）は写真に見えるが、30マス以上では「仮定なしで解ける」条件を満たせなかった（反転が87〜243マス要る）。
濃淡を残したまま解ける形＝**カラーノノグラム**を独立ページ `photo-color.html` で作る。`photo.html` は面／線画のまま残す。

> **現行は末尾の「v0.3 解く枚数を選ぶ」（土台は v0.2 3枚重ね）。** 以下の「ルール」「遊ぶ画面」は v0.1 の記述で、色つき数字とパレットの部分はもう使っていない（写真→問題・共有・保存は共通）。

## ルール（v0.1・既存ジャンルの標準）
- マスは「空」か「3色のどれか」。数字は色つきで、その色の連続マス数を左から／上から並べる
- **同じ色の並びの間は1マス以上空ける。違う色は隣接してよい**（空けなくてよい）
- 全マスが正解と一致した瞬間に完成（途中で正誤は言わない。×メモあり）

## 写真→問題
- 切り取り→N×N（20/30/40、既定30）に平均縮小→k-means（k=4、RGB、反復10、初期値は明るさ四分位で決定的）
- 4クラスタのうち**最も明るい**クラスタを「空」にする。残り3色がパレット（クラスタ平均色をそのまま。彩度が低ければ少し上げて見分けやすく）
- ラインソルバー（色つき）で解けるか判定。解けなければ修復ループ：色の境界で「2番目に近いクラスタ」との距離が小さいマスから順に、そのクラスタへ付け替え→再判定。上限はマス数の6%。無理なら「この写真は難しい」
- 難度ラベルは貼らない（「4色 N×N」とだけ）

## 遊ぶ画面（v0.1）
- パレット（3色＋消す＋×メモ）を盤の下に。選んだ色でタップ塗り・なぞり
- 30×30 は `photo.html` の大盤面と同じ見せ方（スクロール・数字固定・ズームスライダー）。数字は色つきで、色弱でも読めるよう**数字の下に色の点**でなく**数字そのものを色で塗り、さらに色ごとに小さな記号（●▲■）を添える**か、パレットに番号を振る（ui係が決める）
- 完成: 4色の絵と元の写真を並べる（写真は端末にあるときだけ）

## 共有
- `#c1.<w>.<h>.<パレット3色hex>.<マスの状態 2bit×N² を base64url>.<題名>`。30×30 で約320文字、50×50 で約850文字
- 開いた側は復元→数字→ラインソルバー再検証

## 保存
- localStorage キー `pixel-photo-color`（`photo.html` と分ける）。写真本体は保存しない

## 足さないもの
- 5色以上／グラデーション／LLM／サーバー／ヒント／タイマー

## 実装と実測（v0.1・2026-09-08）
- 実装: 単一HTML 1406行。純粋ロジックは `window.PixelColor`（`quantize` / `hints` / `lineDeduce` / `lineSolve` / `solveMasks` / `repair` / `isComplete` / `encode` / `decode`）
- 色つきラインソルバーは前後到達可能性のDP。短いラインの全パターン列挙と4000件照合して一致
- 1色（空＋色1）にすると `photo.html` の白黒ソルバーと完全一致（`index.html` の43問で判定・盤面とも差なし）
- 量子化→修復の成功率: 疑似写真・なめらか色画像・ノイズ画像・純ランダムのいずれも 20/30/40 で **100%**。平均付け替えは 0〜7マス（上限はマス数の6%＝24/54/96）
- `lineSolve` 1回: 20=0.4ms / 30=0.8ms / 40=1.6ms。修復込みでも最悪 50ms
- 共有URL長: 20=280文字 / 30=446文字 / 40=680文字（題名5文字込み）
- **注意**: 1パス目で 85〜87% のマスが確定する。白黒より格段に解けるが、その分やさしい（推理より塗り絵に近い）。難度を上げたいなら色数ではなく「マスをまとめる（同色の塊を大きくする）」方向で

## v0.2 3枚重ね（2026-09-08）

v0.1（4色を同時に解く）は「写真は見えるが、ゲームとして難しすぎる」。
原因は推理の深さでなく**量と読み取り**——1行に3色ぶんの色つき数字が混ざり、どこを見ればいいか決まらない。
そこで**色ごとに1枚ずつ解く**（白黒ノノグラム3枚の重ね刷り）に変える。データ形式と共有ハッシュは v0.1 のまま。

### 遊び方
- 層1「いちばん濃い色」→ 層2「中間」→ 層3「いちばん明るい色」の順（クラスタ平均の明るさ順）
- どの層も**その色だけの白黒ノノグラム**。数字はその層の色のブロックの長さだけ（色つき記号は廃止）。数字はその層の色で塗って、いま何の色を解いているかを示す
- 前の層で確定した色は薄く塗られて見え、その層では塗れない（＝既知の空き）。前の層の色は現在の層のブロックを区切る
- 層が完成したら「1/3 できた」と出して 0.8 秒後に次の層へ。3層目が完成した瞬間に全マスが本来の色になり、既存の完成画面（絵と写真を並べる）へ
- パレットは廃止。ボタンは白黒版と同じ「塗る／✕／もどす／はじめから」。「はじめから」は3枚とも最初から。共有・もう一枚は据え置き

### 問題として成り立つ条件
- v0.1 の「色つきラインソルバーで解ける」から、**各層が順に解ける**へ。層 i の白黒ノノグラムを、層 0..i-1 の色を既知の空きとして与えた状態で、行・列の伝播だけで解けるか。層1は与えなし
- 修復ループの付け替え候補順は据え置き（2番目に近いクラスタとの距離が小さい順、詰まっている層で未確定のマスを優先）。上限もマス数の6%のまま
- 開いたときの再検証（共有ハッシュ）も同じ条件

### 実装
- `window.PixelColor` に `layerHints(cells,w,h,color)` / `layerSolve(cells,w,h,layerIndex,knownMask)` / `layersSolve` / `layersSolvable(cells,w,h)` / `LAYER_COLOR=[3,2,1]` を追加。`layerSolve` は既存の `lineDeduce` を k=1・ブロック色1で呼ぶだけ（白黒ソルバーを別に書かない）
- 色つきの `lineSolve` / `solveMasks` / `hints` は残す（遊びには使わない。1色での白黒ソルバーとの一致検証に使える）
- 保存の途中経過は `<層番号>|<その層の塗り>`（旧形式の数字列は読み捨てて最初から）

### 実測（2026-09-08・実写真20枚＝macOS 標準壁紙の風景写真を中央正方形クロップ→N×N平均縮小）
| マス | v0.2 層方式（通った数・平均付け替え） | v0.1 同時方式 | 層1の1パス確定 | 層2 | 層3 |
|---|---|---|---|---|---|
| 20×20 | 18/20・2.0（最大11） | 20/20・0.0 | 70% | 71% | 86% |
| 30×30 | 13/20・7.0（最大29） | 20/20・0.3 | 66% | 75% | 79% |
| 40×40 | 15/20・25.0（最大68） | 20/20・1.4 | 64% | 67% | 77% |

- 合成画像では、ざらつきのある疑似写真（斑＋ノイズ）は 20/30/40 とも 20/20 が通る（平均0.3〜1.1マス）。のっぺりした帯状のなめらか色画像は 0/20（層1が1マスも確定しない）
- 落ちるのは空・水面・グラデーションなど**大きくのっぺりした面がある写真**。白黒ノノグラムでは長い1本のブロックが行・列に1つだけ並ぶと重なりが出ず、境界マスを付け替えても直らない
- 1パス目の確定率は v0.1 の 85〜87%（盤全体）から層ごと 64〜86% に下がった＝塗り絵から推理側へ寄った。1層あたりの塗るマスは全体の約1/4

### 捨てた案
- **v0.1 同時4色**（色つき数字を1行に混ぜて4色を同時に解く）：写真が通る率は高いが、読み取りの負荷が大きく遊びとして成立しなかった

## v0.3 解く枚数を選ぶ（2026-09-08・現行）

3枚とも解くのは重い。**何枚解くかを写真ごとに選べる**ようにした（v0.2 の3枚重ねはそのまま。解かない層を先に塗っておくだけ）。

### 選択肢（切り取り画面・「これで作る」の前）
- 「解く枚数: 1枚（3枚目だけ）／2枚（2・3枚目）／3枚（全部）」。**既定は1枚**。説明は1行「少ないほどやさしい。塗ってある所から始まる」
- 解くのは**うしろの層**（明るい方）。前の層は最初から塗った状態（薄い色・固定・塗れない＝v0.2 の locked と同じ見せ方）
- 見出し・進み具合は「解く層の番号／解く枚数」（1枚なら1まいめ ／ 1まい、完成すれば即・完成画面）。「はじめから」は解く枚数ぶん最初から

### 難しさの目安（見出しに出す）
- `PixelColor.layerFirstPassRate(cells, w, h, layerIndex)`（DOM 非依存）＝ その層の**1パス目（行→列を一巡）で確定するマス**÷**その層で解くべきマス**（前の層で既知のマスは母数から除く）
- 選んだ枚数ぶんの層の**最小値**でラベルを決める。**閾値は叩き台**: 入門 ≥75% ／ 初級 ≥60% ／ 中級 ≥45% ／ 上級 それ未満
- 見出しは `30×30 ・1枚 ・入門` の形。写真ごとの当たり外れを隠さない（やさしければ「入門」と出る）

### 実測（2026-09-08・30×30・合成画像 各10枚）
| 画像 | 作れた | 1枚 | 2枚 | 3枚 |
|---|---|---|---|---|
| 疑似写真（斑＋ノイズ） | 9/10 | 入門6・初級1・上級2 | 入門2・初級3・中級1・上級3 | 初級3・中級3・上級3 |
| なめらか色（帯・グラデ・弱ノイズ） | 10/10 | 入門8・初級1・中級1 | 入門3・初級4・中級2・上級1 | 入門3・初級4・中級2・上級1 |

- 枚数を減らすほどラベルは軽い側へ寄る（最小値を取る層が減るため）。ただし**1枚でも上級は出る**（層3の1パス確定率が28〜32%の写真があった）＝「1枚＝必ずやさしい」ではない
- 3枚のときのラベルは、v0.2 実測の層別確定率（64〜86%）と整合

### 共有ハッシュ（後方互換）
- `#c1.<w>.<h>.<3色hex>.<マス base64url>.<題名>[.p1|.p2|.p3]`。**末尾の `.pN` は任意**。無ければ **3枚**あつかい（v0.2 までのURLはそのまま開ける）
- 題名の `.` は `%2E` にして書き出す（末尾の `.pN` と混ざらないように）。読む側は従来どおり `decodeURIComponent` なので、古いURLの点入り題名もそのまま読める

### 保存
- `made` の各項目に `play`（1〜3。無ければ3）を足した。一覧は `30×30 3枚` と出す
- 途中経過のキーは 3枚のとき従来どおり `<id>`、1・2枚のとき `<id>|p1` `|p2`（枚数ちがいの続きが混ざらない。古い保存はそのまま読める）

### 変えていないもの
- 量子化・修復・`layersSolvable`（**3層とも順に解ける写真だけ**を問題にする条件は据え置き）。1枚を選んでも「この写真は難しい」で弾かれる範囲は v0.2 と同じ
- ヒント・LLM・タイマーは足さない
